The frontend is a static React + Vite + Tailwind site (no backend yet); all results live in localStorage today. Your job is to build the backend that adds accounts, server-verified scoring, leaderboards, daily games, GOAT voting, contact form, data pipeline, admin panel, and eventually online duels + mobile support.

## Critical Rules (non-negotiable)
1. **Guest mode works everywhere.** Any endpoint that accepts a user must also accept `X-Guest-Id: <uuid>` header. Guests can play every ranked game; they just don't appear in leaderboard.
2. **Server is source of truth.** NEVER trust client-submitted scores. The server issues the seed, rebuilds the puzzle with `game-core`, verifies every answer, and computes the score itself.
3. **Backend down ≠ site down.** Game data is static JSON on CDN. If the API fails, gameplay continues; only ranking is skipped. Frontend stores the failed `finish` call in `futgrid:pending-results` and retries later.
4. **Three languages (az, en, ru).** All error messages and emails localized via `Accept-Language` header. User's locale stored in `users.locale`.
5. **One API, two clients.** Web (React) uses HttpOnly cookies; mobile (Capacitor) uses `Authorization: Bearer <token>`. Same endpoints, both transports supported from day one.
6. **Fixed player IDs.** Never change a player ID once assigned. Use `player_external_ids` mapping table (`tm:418560`, `api:276`, `legend:pele`).
7. **`packages/game-core` is a Phase 1 prerequisite.** Extract pure game rules from `futgrid_app/src/lib/games/`, strip all `fetch`, `localStorage`, and `tr()` dependencies, and make frontend + backend import the same code.
8. **Sessions are single-use and expire** (default 2h). Second `finish` on the same session → 409 CONFLICT. Timing validated server-side (min ms per move).
9. **`points_ledger` is append-only.** Never UPDATE or DELETE. Leaderboard is a Redis projection that can be rebuilt from it.
10. **No secrets in the browser.** Only `VITE_API_URL` is exposed via `VITE_` prefix. Everything else in `.env`.

- `backend/package.json`, `tsconfig.json` (strict), `Dockerfile`, `docker-compose.yml` (Postgres 16 + Redis 7 for local), `.env.example` (keys only), `.gitignore`, ESLint + Prettier.

## 2. Database schema (Phase 1 tables from §15 of the spec)
Create Prisma models for:
`users`, `oauth_accounts`, `refresh_tokens`, `email_tokens`, `teams`, `user_settings`, `guest_links`, `games`, `game_sessions`, `points_ledger`, `user_game_stats`, `leaderboard_snapshots`, `events`.

Every table has `created_at`; add `updated_at` where the spec says so. User/session IDs are UUIDs. Player/club IDs are integers (from players.json). Add all indexes listed in §15.

Use `prisma migrate dev` for all schema changes. Never `prisma db push` outside local scratch.

## 3. `packages/game-core`
Extract pure game logic for the 11 ranked games (all except GOAT) from `futgrid_app/src/lib/games/`. Each game exports a function shaped roughly like:

```ts
export function buildPuzzle(seed: number, settings: Settings): Puzzle
export function verifyAnswer(puzzle: Puzzle, answer: Answer): boolean
export function scoreResult(puzzle: Puzzle, answers: Answer[]): ScoreBreakdown
```

No `fetch`, no `localStorage`, no `tr()`, no `Math.random()` (use the seed with a seeded PRNG). Add unit tests per game verifying:
- same seed → same puzzle (reproducibility)
- known inputs → expected score
- invalid answers → `verifyAnswer` returns false

Update `futgrid_app/src/lib/games/` to import from `@futgrid/game-core` (via workspace path) so frontend and backend run identical code.

## 4. Auth module (`/v1/auth/*`)
- `POST /register` — email (unique, lowercase), password (≥8 chars, argon2id), username (3–20 chars, latin letters + digits + `_`, unique, profanity-checked), display_name (optional, ≤40, supports Azerbaijani letters), team_id (optional), locale (az/en/ru), age_confirmed (required, 16+). Sends verification email (24h token).
- `POST /login` — email+password → sets `access` (15 min) + `refresh` (30 days) cookies, both `HttpOnly; Secure; SameSite=Lax`. For mobile clients (detected via `X-Client: mobile` header or missing cookie jar), return tokens in the response body instead.
- `GET /auth/google` + `GET /auth/google/callback` — OAuth 2.0 (OpenID Connect). If the email exists, link Google to the existing account.
- `POST /refresh` — rotation: hash stored in DB, old token revoked, reuse of old token → revoke all user sessions.
- `POST /logout`, `POST /logout-all`.
- `POST /verify-email` — 24h token, single use.
- `POST /forgot-password` — always returns same response ("If this email is registered, we sent a link") to prevent email enumeration. 1h token, single use.
- `POST /reset-password`.
- Apply rate limits from §17 of the spec.

## 5. User module (`/v1/me`)
- `GET /me` — profile, stats, records.
- `PATCH /me` — display_name, team, locale.
- `PUT /me/settings/:gameKey` — JSONB settings.
- `POST /me/import-guest` — one-time migration of localStorage keys (see spec §19 table). Server validates values, stores as personal records only (NOT ranked points).
- `GET /me/export` — full JSON dump.
- `DELETE /me` — soft delete by default (leaderboard keeps "Deleted user" entry). Document this assumption in `backend/README.md`.

## 6. Session module (`/v1/sessions`)
- `POST /sessions` — body `{ game, mode, difficulty, settings }`. Returns `{ sessionId, seed, dataVersion, expiresAt }`. Works for both users and guests (`X-Guest-Id` header).
- `POST /sessions/:id/finish` — body `{ answers: [{ round, playerId, hints, ms }] }`. Server:
  1. Loads session; checks not expired, not already finished, ownership matches (user or guest).
  2. Rebuilds puzzle from `seed` + `dataVersion` using `game-core`.
  3. Verifies every answer.
  4. Computes score per §6 formula: `points = ratio × 100 × difficultyMultiplier` (easy 0.5, normal 1.0, hard 1.5). Cap at 100.
  5. Checks timing sanity (min ms per move; e.g. XOX 9 cells in <3s rejected).
  6. Applies daily limit: only the first 5 ranked sessions per game per user/guest per day count toward leaderboard; remaining go to stats only.
  7. Writes to `points_ledger`, updates `user_game_stats`, updates Redis sorted sets, checks for `flagged` (20 consecutive perfect scores, or consistently ~1s per answer).
  8. Returns `{ score, points, newRecord, rank, flagged }`.
- `POST /events` — for non-ranked modes ("same screen"): `{ game, mode, durationMs }`. No points.

## 7. Leaderboard module (`/v1/leaderboard`)
Redis sorted sets per §7:
- `lb:week:2026-W46` (TTL 5 weeks)
- `lb:month:2026-11` (TTL 3 months)
- `lb:all` (permanent)
- `lb:week:2026-W46:<game>` (per game, TTL 5 weeks)
- `lb:team:week:2026-W46` (TTL 5 weeks)

Endpoints:
- `GET /leaderboard?period=week|month|all&game=&team=&limit=10` — cached 30s.
- `GET /leaderboard/me` — current user's rank + neighbors.
- `GET /leaderboard/teams` — team ranking = sum of top 5 members' points.

Rules:
- Weekly period resets Monday 00:00 Baku time.
- Only verified + unblocked users appear. Blocked user's points removed from Redis immediately.
- Ties broken by earlier to reach the score.
- If Redis is empty, rebuild from `points_ledger`.
- Cron `leaderboard:snapshot`: Monday 00:00 + 1st of month 00:00 → write top 100 to `leaderboard_snapshots`, open new period.

## 8. Scoring implementation (§6 table — implement in `game-core`)
Implement per-game `score()`:
- XOX: `correctCells / 9` + rarity bonus (stub until Phase 2).
- Ortaq oyunçu: `(correct − wrong) / 10`, min 0.
- Açıq artırma: won 1.0, lost 0.2.
- Yüksək/aşağı: `min(streak / 20, 1)`.
- Wordle: `(7 − attempts) / 6` if solved, else 0.
- Karyera: `(correct − 0.25 × hintsUsed) / 10`.
- Heyəti xatırla: `found / 11`.
- 5 klub: `min(found / 10, 1)`.
- Klubları sırala: `correctBoxes / totalBoxes`.
- Piramida: `found / 15`.
- İki hərf: `min(found / (rounds × 5), 1)`.
- GOAT: no points (voting only — Phase 2).

## 9. Security (§17)
- HTTPS everywhere, `Strict-Transport-Security` header.
- CORS allowlist: `https://futgrid.az`, `https://www.futgrid.az`, `https://staging.futgrid.az`, `capacitor://localhost`, `https://localhost`, `http://localhost:5173`. Everything else rejected.
- CSRF: check `Origin` header on all cookie-based mutations.
- Zod on every request body; unknown fields stripped.
- Passwords: argon2id. Tokens: hashed in DB only. Never logged.
- IPs: salted hash, never plain.
- Rate limits (§17): login 5/min+20/h per IP+email, register 3/h per IP, forgot-password 3/h per IP+email, sessions 60/h per user/guest, daily guess 30/min, goat 20/day per IP, contact 3/h per IP, GET 300/min per IP.
- Use `@fastify/helmet`, `@fastify/cors`, `@fastify/rate-limit`.
- Admin endpoints under `/v1/admin/*`, role checked on every request. TOTP 2FA mandatory for admin (implement in Phase 3).

## 10. Tests
- Unit: every `score()` formula, every game's `verify()`, seed reproducibility (same seed → same puzzle on frontend and backend).
- Integration: full session lifecycle (create → finish → points_ledger → Redis → leaderboard).
- Integration: auth (register → verify → login → refresh → logout), guest migration, double-finish rejection, expired session rejection, invalid answers → 422.
- Use a separate Postgres schema for tests; reset between tests.

## 11. API conventions (§16)
- All endpoints under `https://api.futgrid.az/v1`.
- JSON, camelCase, ISO 8601 UTC timestamps. Daily game dates in Baku time as `YYYY-MM-DD`.
- Error shape:
  ```json
  { "error": { "code": "VALIDATION_FAILED", "message": "...", "details": [{ "field": "...", "rule": "..." }] } }
  ```
- HTTP codes: 400 VALIDATION_FAILED, 401 UNAUTHENTICATED, 403 FORBIDDEN, 404 NOT_FOUND, 409 CONFLICT, 422 INVALID_RESULT, 429 RATE_LIMITED, 500 INTERNAL.
- Pagination: `?limit=20&cursor=...` → response includes `nextCursor`.
- OpenAPI/Swagger exposed at `/docs` (dev/staging only).

# PHASE 2 — Daily & Voting (design now, implement after Phase 1)

## Scope summary (see spec §8, §9, §13 for full detail)
- **Daily XOX**: `daily_puzzles` + `daily_attempts` + `daily_answer_counts` + `daily_streaks`. Same puzzle for everyone, per difficulty. Answer checked server-side. Real rarity = `player_selected_by / correct_in_that_cell`. Daily limit: 1 attempt per user/guest per puzzle. Resume state if page refreshes. Cron `daily:generate` at 00:00 Baku. `daily:close` at 00:05.
- **Daily Wordle**: answer never sent to browser. Each guess checked via `POST /daily/wordle/guess`. Response returns hit/present/miss per letter. Answer revealed only on finish. Same one-attempt-per-day rule.
- **Daily stats**: `GET /daily/:game/stats?date=` — played count, solved %, wordle attempt distribution, XOX average cells filled. Cached 60s.
- **GOAT voting**: `POST /v1/goat/votes` with `{ size, champion, final, semi, picks }`. Validate: `size` ∈ {16, 32, 64, 128}, all IDs in that size list, `picks` = size − 1 pairs, every player loses at most once, champion never loses. One counted vote per user/guest per day (last one wins); others stored but not counted. IP limit 20/day.
- **GOAT ranking**: `GET /v1/goat/ranking?size=128` — champion count, win %, Elo, cached 5 min. Cron `goat:recompute` every 10 min processes new votes into `goat_player_stats` + `goat_pair_stats`.
- **Contact form**: `POST /v1/contact` — name, email, message (≤1000 chars), honeypot field. Stored in `contact_messages`, sent to `info@futgrid.az`. Rate limit 3/h per IP.
- **Homepage stats**: `GET /v1/stats` — counts from data manifest + active user count. Cached 10 min.

# PHASE 3 — Data & Admin (design now, implement after Phase 2)

## Scope summary (see spec §11, §12, §14 for full detail)
- **Data pipeline**: nightly/weekly cron `data:sync` pulls squads from API-Football + Transfermarkt CSV, runs `build-players` logic, writes to Postgres tables (`players`, `clubs`, `player_stints`, `player_trophies`, `coaches`, `countries`, `famous_matches`), applies `data_overrides`, produces a validation report, and publishes a versioned JSON bundle to `cdn.futgrid.az/data/<version>/`. `manifest.json` points to current version. Manifest cached 5 min, version folders immutable + cached 1 year.
- **Image pipeline**: `media` table; new images queued via BullMQ; `sharp` → WebP; hash-based URLs `img.futgrid.az/players/{id}.webp?v={hash}`. Wikimedia images require license + author recorded; add "Image sources" page to site.
- **Admin panel** (`/v1/admin/*`, TOTP 2FA mandatory): overview, users (search/block/role/sessions), ranking control (flagged results, revoke points), contact messages, daily puzzles (view/edit/regenerate), players (edit/hide/upload photo), clubs, data releases (trigger build → view report → publish → rollback), market values (CSV upload/apply), GOAT roster, game catalog (enable/disable, "new" badge, order), audit log.
- **Audit log**: every admin change writes `audit_log` with `before` and `after`.
